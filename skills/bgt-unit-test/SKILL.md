# 단위테스트 결과서 작성 (엑셀 테스트케이스 명세서)

**이 조직의 "단위테스트"는 자동화 테스트가 아니라 엑셀 테스트케이스 명세서**(SI 표준 산출물)다. 화면을 **실제로 브라우저에서 수행**하며 이벤트마다 **창을 캡쳐**하고, 사내 샘플 xlsx 사본에 **Excel COM 으로 채워** 저장한다.

**vitest/jest/JUnit 을 도입하지 말 것.** 이 프로젝트는 러너·스크립트·테스트파일이 0건이고 `package.json` 에 test 스크립트조차 없다. 자동화 테스트로 해석하면 요청 자체를 잘못 수행하는 것이다.

## ⛔ 하지 말 것 — 스킬 없이 접근하면 실제로 하는 실수

이 5가지는 **신규 작업자가 계획 단계에서 실제로 선택한 오답**이다.

1. **`Workbook.SaveAs()` 로 저장하지 말 것.** 민감도 레이블 정책 때문에 **저장이 조용히 실패**한다(COM 오류인데 "OK" 처럼 보이고 파일은 그대로). → §저장 참조.
2. **`Visible=$false` / `DisplayAlerts=$false` 로 저장하지 말 것.** 레이블 창이 못 떠서 위 실패가 확정된다. **`Visible=$true` 로 띄운 채 두고 종료**한다.
3. **`$xl.Quit()` 하지 말 것.** 사용자가 Ctrl+S 할 기회가 사라진다.
4. **1194 해상도를 먼저 잡고 전 케이스를 수행하지 말 것.** 뷰포트 에뮬레이션이 세션에 눌러붙어 **이후 캡쳐가 전부 오염**된다. 1194 는 **맨 마지막 1건**. → `references/browser-capture.md`
5. **샘플 잔존 이미지를 `Shapes.Delete()` 로 지우려 하지 말 것.** 안 지워진다(셀에 배치 이미지). → `Range("B2:B39").ClearContents()`

## 환경 전제

없으면 착수 전에 사용자에게 요청한다.

| 필요 | 확인 |
|---|---|
| **샘플 원본 xlsx** (사내 서식) | 경로를 사용자에게 받는다. **처음부터 새 통합문서를 만들지 말 것** — 헤더/시트구성/공통체크를 재현할 수 없다 |
| **Windows + Excel + PowerShell 5.1** | Excel COM 이 유일한 작성 수단. Python 은 설치 여부가 PC마다 다르니 **먼저 확인하고**(`Get-Command python`) 결과에 맞춰 진행한다. 단 설치돼 있어도 openpyxl·SheetJS 는 **이미지·서식이 유실**되어 부적합 |
| **민감도 레이블(Purview) 정책 계정** | 저장 흐름이 여기에 종속 |
| **Playwright MCP + 디버깅 Chrome** | 화면 실수행·캡쳐 |
| **로컬 앱 기동** | host 셸 + 대상 remote. 포트·라우팅은 프로젝트 실행 문서 참조 |

## 0. 인테이크 (7항목)

```
1. 단위테스트ID       예) UT_{시스템}-{업무}-{INQ|UPD|POP}-W-{번호}
2. 작성대상화면        화면명 + 경로/URL (팝업이면 진입 경로까지)
3. 해상도 1194        테스트 필요 / 해당사항 없음
4. 엑셀 다운로드       테스트 필요 / 해당사항 없음
5. 산출물 저장 경로·파일명
6. 단위테스트명        파일명·시트 헤더에 들어감
7. 케이스 도출 방식     이벤트 기반 (기본값)
```
3·4번은 공통체크 Pass/N/A 의 근거다. 비어 있으면 물어본다. **경로·명칭·프로그램ID 는 추측 금지.**

추가로 확인할 것 — 요청서에 대개 빠져 있다:
- **저장·상태전이·메일발송을 실제로 수행해도 되는지** (DEV 라도 데이터가 남고 알림이 나갈 수 있다)
- **캡쳐 속 개인정보(담당자명·이메일) 마스킹 필요 여부** — 결과서는 배포 문서다

## 1. 착수 전 사전확인 (필수 — 결과를 보고한 뒤 진행)

**코드를 읽기 전에** 실측하고 결과를 보고한다. 아래 3건은 과거 요청서에서 실제로 틀렸던 항목이다.

| # | 확인 | 방법 | 틀렸을 때 |
|---|---|---|---|
| 1 | 저장 경로 실존 | `Test-Path` | 실제 경로로 보정. **새 폴더를 만들지 말 것** |
| 2 | 동일 파일명 존재 | `Get-ChildItem <결과폴더> -Filter "*<번호>*"` | **덮어쓰기다.** "덮어쓰기 / 접미사 붙여 신규 / 중단" 확인 |
| 3 | ID ↔ 작성대상화면 ↔ 단위테스트명 3자 정합 | 결과폴더의 기존 산출물명과 대조 | 아래 규칙 |
| 4 | 재작성이면 대상 화면 변경 여부 | `git log -- <화면 경로>` | 무변경이면 재작성 실익이 없음을 보고 |

**3자 불일치 판정**: **ID + 작성대상화면이 서로 맞으면 그 둘이 정본**이고 단위테스트명이 오기다(다른 회차 값이 복사돼 온 것). 화면명 기준으로 보정하되 **반드시 고지**한다.

## 2. 표준 워크플로우

1. **화면 코드 분석 → 이벤트 전수 추출**(케이스 후보). 상세 `references/authoring-workflow.md`
2. **케이스 실행 순서 설계** — ⚠ 저장·상태전이는 **후속 케이스의 전제를 파괴**한다. `읽기전용/검증실패 → 임시저장 → 상태전이` 순으로 배치하고, 상태별 분기 케이스는 **다른 대상 행**을 준비한다.
3. **브라우저 실수행 + 케이스별 창 캡쳐**. 1194 는 마지막. `references/browser-capture.md`
4. **캡쳐 → 케이스 번호 매핑 + 데이터 JSON 작성**
5. **빌드 스크립트 실행** → 샘플 사본에 채우고 **Excel 을 띄운 채 종료**
6. **사용자에게 저장 요청** → §저장
7. **검증** → §검증

## 3. 케이스 도출 = 이벤트 기반

**이벤트 1개 = 케이스 1개.** 검증 실패 분기(alert/toast/confirm 취소)도 각각 케이스로.

시나리오 흐름형으로 묶으면 **개별 이벤트가 조용히 누락**된다. 실제로 시나리오형 11건으로 작성했다가 누락 지적을 받아 재작성했고 **22건**이 나왔다. 부수 효과로 입력제한·자릿수·필수미입력·유효성체크 공통항목이 **N/A → Pass** 로 전환된다(실제로 검증하게 되므로).

## 4. 산출물 규약

- **저장 경로·파일명**: 인테이크 5번. ⚠ 요청서 경로에 **오타가 잦다**(폴더명 공백 등) → 반드시 `Test-Path`.
  ⚠ 단위테스트명에 `/` 등 Windows 금지문자가 있으면 **파일명만 치환**하고 엑셀 헤더는 원문 유지.
  ⚠ 저장 경로가 저장소 작업범위 밖이면 저장 전 사용자 확인.
- **샘플 원본**: **수정 금지**, 사본 작성. 읽기는 `Workbooks.Open($p,$null,$true)`.
- **시트**(이름 아닌 **인덱스** 접근 — 한글 시트명 비교가 깨진다):

  | # | 시트 | 구조 |
  |---|---|---|
  | 1 | 테스트케이스 | R1 헤더(ID/명) · R3 컬럼헤더 · **R4~ 케이스**(순번/내용/데이터/예상결과/관련프로그램ID/수행결과/비고) |
  | 2 | 테스트결과 | 순번별 스크린샷, **B열** |
  | 3 | 공통체크항목 | **R3~R49(47행)**, **D열** 에 Pass/N/A |

- **ID 규칙**: 구분 = 조회 `INQ` / 편집·저장 `UPD` / 팝업 `POP`. 관련프로그램ID = `UT_` 뗀 값.
  ⚠ **팝업이면서 저장을 수행하면 `POP` 이 아니라 `UPD`** 다(동작이 구분을 결정한다). ID 는 사용자가 주는 값이 정본이니 **임의로 바꾸지 말고**, 관례와 어긋나 보이면 §1 사전확인에서 고지만 한다.
- 수행결과는 **실제 수행한 것만 Pass**. 미수행은 사용자 지시에 따라 처리하고 비고에 근거를 남긴다.

## 5. 저장 — 에이전트가 할 수 없다

민감도 레이블 정책이 `mandatory` 라 **레이블 없이 저장이 불가**하고, 코드로 레이블을 지정(`SensitivityLabel.SetLabel`)하면 **컴플라이언스 우회로 차단**된다.

→ **에이전트는 내용만 채우고 Excel 을 띄운 채 종료**, 사용자가 **Ctrl+S**. 안내 문구:

> Excel 을 띄워뒀습니다. **Ctrl+S → 민감도 레이블 "개인한(Private)" 선택 → "특정인원 권한설정"은 건너뛰기** 로 저장해 주세요.

⚠ **사내한(Company) = 암호화 → 저장 실패**. ⚠ **개인한이어도 권한설정을 붙이면 암호화**된다(레이블ID는 같은데 결과가 다름).

## 6. 검증

사용자 저장 후 **사본을 떠서** 검사한다(원본을 열거나 Excel 을 Kill 하면 미저장분 유실. 점유 중이면 `FileShare::ReadWrite`).

⚠ **매직바이트로 판정하지 말 것.** 이 환경 산출물은 정상이어도 `D0CF`(레이블이 OLE 컨테이너로 감쌈)다. `ZipFile` 기반 내부 검사도 그래서 **수행 불가**하다.

**COM 으로만 판정**: ① 암호 프롬프트 없이 오픈 ② 헤더(ID/명/프로그램ID) 일치·샘플 잔재 없음 ③ 케이스 수 일치 ④ `Shapes.Count` = 캡쳐 수 ⑤ `B2:B39` 잔존 0 ⑥ 공통체크 집계.
보조 신호: 캡쳐가 박혔다면 파일이 **MB 단위**다. 수십 KB 면 이미지 삽입 실패.
